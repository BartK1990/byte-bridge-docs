ByteBridge connects to IEC 61850 IEDs (protection relays, bay controllers, meters) as an MMS
client (IEC 61850-8-1, Edition 2, and Edition 1 where it behaves the same). It reads their data
objects with the IED's own quality and time stamps, takes changes from the IED's **reports**,
operates controllable objects with the IED's **control model**, and can **detect** the points
of an IED by browsing its model.

Add an endpoint with the protocol **IEC 61850 (MMS)** and the role **Client**. One endpoint is
one IED; a station gets one endpoint per IED.

## Connection

| Setting | Example | Notes |
|---|---|---|
| Host | `192.168.10.21` | the IED |
| Port | `102` | |
| Password | | only for IEDs with ACSE password authentication |
| Remote TSEL / SSEL / PSEL | `0001` / `0001` / `00000001` | the defaults of nearly every IED |
| Remote AP title / AE qualifier | `1.1.1.999.1` / `12` | empty unless the IED asks for them |

If the IED is configured otherwise, its SCL file (CID or SCD) has the values under
`ConnectedAP/Address`: `OSI-TSEL`, `OSI-SSEL`, `OSI-PSEL`, `OSI-AP-Title`,
`OSI-AE-Qualifier`. Some IEDs accept only clients they know: then set **Local AP title** and
**Local AE qualifier** as listed in the IED's configuration.

## Points

A point is an **object reference** with its functional constraint, written as the IED's
engineering tool shows it:

| Point | What it reads |
|---|---|
| `IED1CTRL/XCBR1.Pos[ST]` | breaker position (`stVal`, a double point) with its quality and time |
| `IED1LD0/MMXU1.TotW[MX]` | total active power (`mag.f`) |
| `IED1LD0/MMXU1.PhV.phsA[MX]` | phase A voltage |
| `IED1LD0/MMTR1.TotWh[ST]` | energy counter (`actVal`) |
| `IED1PROT/PTOC1.Op[ST]` | protection operate (`general`) |
| `IED1CTRL/XCBR1.Pos[CO]` | the breaker as a controllable object: shows its position, takes commands |
| `IED1LD0/GGIO1.SetPt.setMag.f[SP]` | an attribute named in full |

A point that names a data object reads its value attribute (`stVal`, `mag.f`, `actVal`,
`general`, `setMag.f`, ...). For other data objects, name the attribute. Names are
case-sensitive, as in the IED.

| IEC 61850 | Point type |
|---|---|
| BOOLEAN | Boolean |
| Dbpos | DoublePoint (0 intermediate, 1 off, 2 on, 3 bad) |
| integers, enumerations | Integer (`actVal`: Counter) |
| FLOAT32, FLOAT64 | Float |

The IED's quality becomes the usual flags: invalid → **IV**; questionable and old data →
**NT**; overflow → **OV**; substituted → **SB**; operator blocked → **BL**. Every quality flag
the IED sets, including *test* and *failure*, is named in the point's reason. The time stamp is
the IED's own.

A point the IED does not have stays invalid with the reason, for example *the IED's XCBR1 has no
'Pos2'*; the other points are read.

## Reports or polling

In the default mode, **Reports**, ByteBridge uses the IED's report control blocks: it enables
every block whose data set holds one of the points (or the blocks you list in **Report control
blocks**, e.g. `IED1LD0/LLN0.brcbMX01[BR]`) and asks for all their values once. After that the
IED sends changes as they happen. Points that no report covers are polled every **Poll
interval**.

- **Buffered** blocks (`[BR]`) keep the events while the connection is down; after a reconnect
  ByteBridge continues where it stopped, so no event is lost and none is repeated.
- A block that another client (often the station SCADA) already uses is left alone: its points
  are polled, and the endpoint's health names the block. With **When an RCB cannot be used** set
  to *Fail*, the endpoint does not go online instead, for sites where reports are required.
- **Integrity period** asks the IED to repeat all values of a block that often.

The mode **Poll** reads every point each poll interval and uses no report control blocks.

## Commands

Send a command to a `[CO]` point. ByteBridge runs the object's control model as the IED has it
configured (`ctlModel`):

| Control model | What happens |
|---|---|
| direct, normal security | the IED operates at once |
| select before operate, normal security | ByteBridge selects the object, then operates |
| direct, enhanced security | ByteBridge operates and waits until the IED reports the end of the operation |
| select before operate, enhanced security | select, operate, and wait for the end |
| status only | the command is refused |

For a double point (a breaker, a disconnector) send `2` to close (on) and `1` to open (off). If
the IED refuses, the command fails with the IED's own reason, for example *blocked by
interlocking*, *object already selected* or *blocked by switching hierarchy* (the IED is in
local mode). **Originator category** (default *RemoteControl*) and **Originator identification**
are sent with each command; **Interlock check** and **Synchro check** ask the IED to check before
operating.

Commands to settings (`[SP]`, `[SE]`, `[CF]`, ...) write the value. Status (`[ST]`) and
measurements (`[MX]`) are read-only; command the `[CO]` point instead.

## Detect points

You do not need the IED's point list: **Detect points** on the endpoint's page browses the
IED's model and proposes one point per data object: status and measurements, and on request the
controllable objects (`[CO]`) and the settings and configuration. Pick the ones you want and add
them. With **Detect points on connect** the endpoint adds the status and measurement points by
itself each time it connects.

## When it does not connect

**Test connection** (or the **Troubleshoot** tab) walks through the steps and stops at the first
one that fails, with what to change:

| Step | Typical failure | What to check |
|---|---|---|
| Transport connection | the IED refuses the transport selector | **Remote TSEL** |
| Association | session or presentation selector unknown; AP title not recognised; password required or wrong; the IED closes the connection without an answer | **Remote SSEL**, **Remote PSEL**, **Remote AP title**, **Password**, the IED's list of allowed clients |
| MMS initiate | the IED refuses the PDU size | **Max PDU size** (try 32000) |
| Identification | the IED does not support Identify | nothing: it is not needed |
| Logical devices | no logical devices | the IED's configuration (CID file) |
| Configured points | a reference the IED does not have | the object reference, or detect the points |

The frame trace shows every message with its meaning: reads with object references and values,
reports with the members of their data sets, the steps of each command and the IED's reasons.

## No IED at hand?

The [ByteBridge repository](https://github.com/BartK1990/byte-bridge) has a test IED with
measurements that move, report control blocks and controllable objects of every control model:

```bash
cargo run -p iec61850 --example iec61850_server_sim -- 127.0.0.1:10102
```

Connect an endpoint to host `127.0.0.1`, port `10102`, and detect its points, or use
`BBSIMLD0/MMXU1.TotW[MX]` and `BBSIMLD0/XCBR1.Pos[CO]`.
